# 版本说明书

## 版本配套说明

本文说明 `v3.0.0` 的配套环境、交付文件和主要变更，并在“开发分支后续变更”中单列尚未包含在该版本中的修改。正式发布信息见 [CinderX Releases](https://gitcode.com/openeuler/cinderx/releases)。构建和用户指南按本页列出的开发基线编写；使用发布包时，应同时核对对应版本的要求。

| 产品 | 版本信息 |
|---|---|
| 产品名称 | CinderX 鲲鹏／ARM 优化版 |
| 正式版本 | `v3.0.0` |
| 发布日期 | 2026-11-10 |
| 发布源码提交 | `cebb4ca7c5c46e9d9e034a9da4d7222bb6292724` |
| wheel 包版本 | `2026.11.10.0` |
| 发布前一版本 | `v2.2.3` |
| 资料核对日期 | 2026-11-12 |

发布 Tag 与 Python 包版本采用不同规则。源码构建默认生成日期型版本 `YYYY.MM.DD.PP`：日期可由 `SOURCE_DATE_EPOCH` 固定，末段补丁号由 `CINDERX_VERSION_PATCH` 指定；从源码分发包构建时则沿用其包元数据版本。因此 `v3.0.0` 安装后查询到的包版本是 `2026.11.10.0`。

## 软件版本配套信息

本节分别列出 CPython 3.11 和 3.14 的发布制品。两类 wheel 不能互换，均面向 Linux AArch64；本次发布未提供 x86_64 wheel。

### CPython 3.11

| 项目 | 配套信息 |
|---|---|
| Python | CPython 3.11.6 |
| 操作系统 | openEuler 24.03 LTS-SP3，使用下列指定版本的发行版 Python 包 |
| 发行版包 | `python3-3.11.6-34.oe2403sp3`；构建时使用同 NVR 的 `python3-devel` |
| wheel | `cinderx-2026.11.10.0-cp311-cp311-linux_aarch64.whl` |
| 校验文件 | 同名 wheel 加 `.sha256` 后缀 |
| 启动方式 | 插件开关、`CINDERX_EVAL_MODE=cinder`、`CINDERX_JIT_MODE=execute` 和数值阈值 |
| 能力限制 | 不支持 `auto`／`auto:N` 行为分类、OSR 和轻量级帧执行 |

该 wheel 为普通 Linux wheel，不是 CP314 fat wheel，也不承诺兼容所有提供 Python 3.11.6 的 Linux 发行版。

### CPython 3.14

| 项目 | 配套信息 |
|---|---|
| Python | CPython 3.14.0—3.14.3，推荐 3.14.3 |
| 操作系统 | Linux AArch64，推荐 openEuler 24.03 LTS-SP3；需满足 wheel 的平台标签和动态库依赖要求 |
| wheel | `cinderx-2026.11.10.0-cp314-cp314-manylinux_2_24_aarch64.manylinux_2_28_aarch64.whl` |
| 校验文件 | 同名 wheel 加 `.sha256` 后缀 |
| 包形态 | fat wheel，包含四个补丁版本对应的本地扩展及加载器 |
| 能力限制 | CPython 3.14.0 的直接调用路径绕过 AutoJIT 分类准入；OSR 与轻量级帧互斥 |

这里的补丁版本（micro）指 3.14.0、3.14.1 等版本。加载器只选择包内已经提供的扩展，因此该 wheel 不支持 3.14.4 及后续版本。Python 3.15、自由线程版本（free-threaded Python）及表外构建形态不在本次配套范围内。

## 版本更新说明

### v3.0.0 更新说明

以下摘要整理自正式 Release 的变更记录，便于用户了解升级影响；完整提交列表见发布页。

- 扩展 CP311 JIT 的调用和参数绑定、属性／方法缓存、生成器及异常处理等执行路径。
- 优化 CP311 整数、浮点、下标访问、循环数值和 HIR／代码布局等路径。实际收益随程序和配置变化，发布摘要不提供统一加速倍数。
- 将面向 CPython 3.11 的 CinderX 构建流程的 PGO 和 LTO 默认值设为开启，PGO 使用仓库训练场景。具体制品的参数以构建记录为准。
- 改进 AutoJIT 的循环感知 IC 稳定性检查。

### v3.0.0 已解决的问题

- 修复 CP311 quickened-code 计数、tracing 回调入口保护，以及异常边界的状态处理。
- 修复生成器运行／挂起状态、委托与 finalizer 处理的若干问题。
- 修复引用计数、内联目标生命周期、并行编译期间类型监视注销等正确性问题。
- 修复代码补丁标志初始化、过大编译输入处理和 LIR／寄存器分配确定性等问题。

上述修复和优化均有各自的适用条件。JIT 只编译其支持的函数形态，其他形态可能继续解释执行。

### 开发分支后续变更

本次资料所核对的开发基线为 `7d0f10e62dfa3cbc1211b091de011ee6bea8c40c`。相对 `v3.0.0`，主要后续变更包括：

- `!285`：CP311 在 import／setup 作用域内跳过帧观察器。
- `!286`：降低 CP311 参数绑定与共享编译入口开销。
- `!289`：修正 CP311 refcycle 引用计数验收，并保留生命周期检查。

上述变更需要从对应开发提交构建，未包含在本页列出的 `v3.0.0` wheel 中。测试结果和性能数据也应与实际测试的提交及构建配置对应。

### 遗留问题与使用限制

- OSR 为 CP314 实验能力，默认关闭；不能与轻量级帧同时开启。
- CP311 设置轻量级帧开关后仍使用普通帧，不能据此认为轻量级帧已生效。
- CP311 不支持 AutoJIT 行为分类；CP314 的分类准入也可能延后或拒绝某个函数，不能把调用次数等同于必然编译。
- 依赖 frame、trace／profile、异常栈或其他运行时内部行为的应用，应验证其业务路径。
- 已知问题的后续状态以所选 Release 说明、相关 Issue 和当前代码为准。
